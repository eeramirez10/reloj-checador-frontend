# Flujo de trabajo Git

- Usar `development` como base de integración.
- Antes de una función o corrección nueva, crear una rama desde `development`: `feature/<nombre>` o `fix/<nombre>`.
- Si el trabajo continúa el mismo feature, seguir en su rama actual; no crear otra por cada ajuste.
- Verificar el estado y la rama antes de editar. Conservar los cambios existentes al cambiar de rama.
- Crear commits, integrar ramas o publicar cambios únicamente cuando el usuario lo solicite.
